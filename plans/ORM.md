لجعل قاعدة بيانات مشروع مفتوح المصدر مرنة وقابلة للاتصال بأي نوع من قواعد البيانات (Database Agnostic)، يجب عليك **فصل منطق التطبيق عن منطق قاعدة البيانات** باستخدام طبقة تجريد (Abstraction Layer).

إليك الطريقة المثالية لتحقيق ذلك:

### 1. استخدام مكتبات الـ ORM (Object-Relational Mapping)
بدلاً من كتابة استعلامات SQL خام (Raw SQL) التي قد تختلف بين MySQL و PostgreSQL و SQLite، استخدم مكتبة ORM قوية. هذه المكتبات تقوم بترجمة الأوامر البرمجية إلى لغة SQL الخاصة بقاعدة البيانات المستخدمة تلقائياً.

*   **أمثلة:**
    *   لـ Node.js: `Prisma` أو `Sequelize`.
    *   لـ Python: `SQLAlchemy` أو `Django ORM`.
    *   لـ PHP: `Eloquent`.

### 2. اعتماد نمط "مستودع البيانات" (Repository Pattern)
هذا النمط يضمن أن الكود الخاص بك لا يتصل بقاعدة البيانات مباشرة، بل يتصل "بواجهة" (Interface). إذا قررت تغيير قاعدة البيانات لاحقاً، ستقوم فقط بتغيير "المُنفذ" (Implementation) داخل المستودع دون لمس كود التطبيق الأساسي.

### 3. استخدام متغيرات البيئة (Environment Variables)
لا تقم أبداً بكتابة بيانات الاتصال (مثل `localhost` أو اسم المستخدم) داخل الكود. استخدم ملفات الإعدادات (مثل `.env`) لتحديد نوع قاعدة البيانات ورابط الاتصال.

---

### مثال توضيحي (باستخدام Node.js و Prisma)

تخيل أن لديك مشروعاً يحتاج للتعامل مع "المستخدمين". بدلاً من كتابة `INSERT INTO users...`، سنستخدم **Prisma**.

#### الخطوة 1: تعريف النموذج (Schema)
في ملف `schema.prisma`، نحدد شكل البيانات فقط:

```prisma
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}
```

#### الخطوة 2: تغيير نوع قاعدة البيانات (بدون تغيير الكود)
عندما تقوم بتثبيت المشروع، يمكنك تغيير نوع قاعدة البيانات من خلال ملف `.env` فقط، ولن يحتاج مطور المشروع لتغيير سطر واحد من الكود البرمجي:

**إذا كنت تستخدم PostgreSQL:**
`DATABASE_URL="postgresql://user:password@localhost:5432/mydb"`

**إذا كنت ترغب في التبديل لـ MySQL لاحقاً:**
`DATABASE_URL="mysql://user:password@localhost:3306/mydb"`

#### الخطوة 3: كود التطبيق (موحد)
الكود الذي تستخدمه لإضافة مستخدم سيكون دائماً هكذا، بغض النظر عن نوع قاعدة البيانات في الخلفية:

```javascript
// هذا الكود يعمل مع أي قاعدة بيانات تدعمها Prisma
const newUser = await prisma.user.create({
  data: {
    name: 'Ahmed',
    email: 'ahmed@example.com',
  },
})
```

### تحديث: استخدام Drizzle ORM في Arkan

بعد التقييم، تم اعتماد **Drizzle ORM** كخيار أساسي للمشروع بدلاً من Prisma لعدة أسباب تقنية تتعلق بالأداء في بيئات Serverless وتوافقها العالي مع TypeScript. 

لضمان بقاء المشروع مرناً وقابلاً للاتصال بقواعد بيانات مختلفة (Database Agnostic)، تم تطبيق المعايير التالية:

1. **نمط المستودع الموحد (Standardized Repository Pattern):**
   تمت تسمية جميع المستودعات ببادئة `Drizzle` (مثل `DrizzleProjectRepository`) بدلاً من تخصيصها لنوع قاعدة البيانات، مما يعني أن المنطق يعتمد على الـ ORM وليس المحرك (Engine).

2. **تجنب العمليات المخصصة للمحرك (Avoid Dialect-Specific Methods):**
   يتم كتابة الاستعلامات باستخدام وظائف Drizzle العامة (مثل `select().limit(1)`) وتجنب الوظائف الحصرية لـ SQLite (مثل `.get()` أو `.run()`).

3. **مركزية الاتصال (Centralized DB Client):**
   يتم إدارة الاتصال في `src/infrastructure/db/index.ts` حيث يمكن تبديل المشغل (Driver) من `better-sqlite3` إلى `pg` أو `mysql2` بسهولة عبر متغيرات البيئة.

4. **العمليات غير المتزامنة (Async Operations):**
   جميع عمليات قواعد البيانات مصممة لتكون `async` بشكل افتراضي، مما يضمن التوافق مع أي محرك قاعدة بيانات مستقبلي.

بهذا الالتزام، يجمع Arkan بين سرعة Drizzle ومرونة الأنظمة Agnostic.
