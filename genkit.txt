# Genkit: Flow, Prompts, Tools Relationship.



Model

سؤال ممتاز يلامس صميم فلسفة عمل مكتبة genkit (المعروفة سابقاً باسم genkit typescript)، خاصة في سياق تصميم تدفقات (Flows) معقدة تستفيد من الذكاء الاصطناعي (AI).

في genkit، تعمل المكونات الثلاثة (Flows - Prompts - Tools) بتناغم لإنشاء تطبيقات ذكية وقوية.

---

## العلاقة بين Flow - Prompts - Tools في Genkit

يمكن تلخيص العلاقة بأن **Flow** هو المايسترو (المدير)، و **Prompts** هي التعليمات الموجهة (التواصل مع الـ LLM)، و **Tools** هي المهارات التخصصية (التفاعل مع العالم الخارجي).

|   |   |   |
|---|---|---|
|المكون|الدور في النظام (التعريف)|العلاقة بالمكونات الأخرى|
|**1. Flow (التدفق)**|هو التسلسل المنطقي للعملية بأكملها. يحدد متى وكيف يتم استدعاء الـ LLM، ومتى يجب استخدام أداة معينة، وكيفية معالجة النتائج.|**يستدعي Prompts** لتنفيذ خطوات الذكاء الاصطناعي، و **يُفعل Tools** عندما يحتاج إلى معلومات خارجية أو إجراءات.|
|**2. Prompts (المحفزات/التعليمات)**|هي الواجهة النصية التي يتم تمريرها إلى نموذج اللغة الكبير (LLM). تحدد المهمة المطلوبة، السياق، والشخصية التي يجب أن يتخذها النموذج.|**يُستخدم داخل Flow** كخطوة محددة. قد تشمل مخرجات الـ Tool كجزء من سياقها (Prompt Context).|
|**3. Tools (الأدوات)**|هي وظائف أو APIs خارجية تمكن الـ LLM من "رؤية" العالم الخارجي، إجراء عمليات حسابية، البحث في قاعدة بيانات، أو استدعاء خدمة.|**يتم تسجيلها في Genkit** ويتم استدعاؤها بواسطة الـ LLM (أو داخل الـ Flow مباشرة) عندما يقرر أن المهمة تتطلب قدرة خارج قدراته النصية الأساسية.|

### تسلسل العمل النموذجي

1. **البداية:** يتم استدعاء الـ **Flow**.
    
2. **التخطيط:** يرسل الـ **Flow** أول **Prompt** للـ LLM (مثل: "ما هي خطة العمل؟").
    
3. **التخصص:** يقرر الـ LLM (أو الـ Flow) أن مهمة معينة تتطلب بيانات حديثة.
    
4. **التنفيذ:** الـ LLM يستدعي **Tool** (مثل: searchEngineTool) للحصول على البيانات.
    
5. **العودة:** تعود نتيجة الـ **Tool** إلى الـ **Flow**.
    
6. **الإنهاء:** الـ **Flow** يمرر نتيجة الـ **Tool** كجزء من **Prompt** جديد للـ LLM ليقوم بصياغة النتيجة النهائية.

## مثال متكامل: كتابة مقطع "المراجعة الأدبية" في مستند أكاديمي

دعنا نفترض أن لدينا نظاماً آلياً في Genkit مهمته كتابة مقطع "المراجعة الأدبية" (Literature Review) لموضوع محدد، مع التأكد من أن المراجع حديثة ودقيقة.

### 1. تعريف الأدوات (Tools)

نحتاج إلى أداة للبحث في قواعد البيانات الأكاديمية (مثل PubMed أو Google Scholar API).

**اسم الأداة:** academicSearchTool  
**الوظيفة:** تبحث عن أحدث خمسة مقالات حول موضوع معين وتلخص عنوانها والمؤلف وتاريخ النشر.

codeTypeScript

```
// tool.ts
import { defineTool } from '@genkit-ai/ai';

export const academicSearchTool = defineTool(
  {
    name: 'academicSearchTool',
    description: 'يستخدم للبحث عن المراجع الأكاديمية الحديثة (خمسة نتائج) لموضوع معين.',
    input: {
      type: 'object',
      properties: {
        topic: { type: 'string', description: 'الموضوع الأكاديمي للبحث.' },
      },
      required: ['topic'],
    },
    output: { type: 'string' }, // إرجاع قائمة بالمراجع الملخصة
  },
  async ({ topic }) => {
    // محاكاة لنتيجة بحث API حقيقية
    console.log(`Executing search for topic: ${topic}`);
    return `
      [REF 1]: العنوان: "تأثير النمذجة اللغوية الكبيرة على الأبحاث الأكاديمية" (2024). المؤلف: د. علي أحمد.
      [REF 2]: العنوان: "تحديات تطبيق التعلم الآلي في التحليل النصي" (2023). المؤلف: أ. نورة خالد.
      [REF 3]: العنوان: "إطار عمل جديد لتصنيف البيانات غير المهيكلة" (2022). المؤلف: فريق الباحثين.
    `;
  }
);
```

### 2. تعريف المحفزات (Prompts)

نحتاج إلى محفزين رئيسيين:

- **Prompt 1 (initial_request_prompt):** لتحديد خطة العمل والبحث.
    
- **Prompt 2 (final_draft_prompt):** لصياغة المراجعة الأدبية النهائية باستخدام نتائج البحث.
    

codeTypeScript

```
// prompts.ts (هذا جزء تعريفي يتم تمريره لـ LLM)

const INITIAL_REQUEST_PROMPT = (topic: string) => ({
  message: `أنا بصدد كتابة مراجعة أدبية للموضوع التالي: "${topic}".
  مهمتك الأولى هي تحليل الموضوع وتحديد الكلمات المفتاحية الأكثر أهمية التي يجب أن يستخدمها الباحث في الأداة الخارجية (academicSearchTool) للحصول على أحدث المراجع.
  لا تقم بالإجابة، فقط قم باستدعاء الأداة (academicSearchTool) بالكلمات المفتاحية المناسبة.`,
  // يتم هنا تمرير الأدوات المتاحة للـ LLM
});

const FINAL_DRAFT_PROMPT = (topic: string, searchResults: string) => ({
  message: `باستخدام نتائج البحث الأكاديمي التالية:
  ---
  ${searchResults}
  ---
  قم بصياغة فقرة نقدية متماسكة ومحايدة (ما بين 150-200 كلمة) تشكل مقطع "المراجعة الأدبية" (Literature Review) حول الموضوع: "${topic}".
  يجب أن تتبع الصياغة الأسلوب الأكاديمي الرفيع وأن تشير إلى أهمية الأبحاث الحديثة المذكورة أعلاه.`,
});
```

### 3. بناء التدفق (Flow)

الـ Flow هو الذي ينسق استخدام الـ Prompts والـ Tools.

codeTypeScript

```
// flow.ts
import * as z from 'zod';
import { defineFlow, generate } from '@genkit-ai/flow';
import { gemini } from '@genkit-ai/gemini';
import { academicSearchTool } from './tool';
import { INITIAL_REQUEST_PROMPT, FINAL_DRAFT_PROMPT } from './prompts';

export const academicReviewFlow = defineFlow(
  {
    name: 'academicReviewGenerator',
    input: z.object({
      topic: z.string().describe('الموضوع الذي سيتم كتابة المراجعة الأدبية عنه.'),
    }),
    output: z.string(), // النص النهائي للمراجعة الأدبية
  },
  async ({ topic }) => {
    
    // --- الخطوة 1: استخدام LLM لتخطيط البحث (تفعيل Tool) ---
    console.log('STEP 1: Asking LLM to plan the search...');
    
    const searchPlanResponse = await generate({
      model: gemini.chat(), // استخدام نموذج LLM
      config: {
        tools: [academicSearchTool], // إتاحة الأداة للـ LLM
      },
      prompt: INITIAL_REQUEST_PROMPT(topic),
    });

    // إذا لم يقم LLM باستدعاء الأداة بشكل صحيح، قد نحتاج إلى معالجة خطأ هنا.
    // نفترض أن LLM قام باستدعاء الأداة (Tool Call) بنجاح.
    if (!searchPlanResponse.toolCalls || searchPlanResponse.toolCalls.length === 0) {
        throw new Error("LLM failed to call the academic search tool.");
    }
    
    // تنفيذ استدعاء الأداة الفعلية
    const toolCall = searchPlanResponse.toolCalls[0];
    const toolResult = await academicSearchTool.run(toolCall.args);
    
    console.log('STEP 2: Tool execution complete. Results:', toolResult);

    // --- الخطوة 3: استخدام LLM للصياغة النهائية (Prompt جديد) ---
    console.log('STEP 3: Sending results to LLM for final drafting...');
    
    const finalDraftResponse = await generate({
      model: gemini.chat(),
      prompt: FINAL_DRAFT_PROMPT(topic, toolResult), // استخدام الـ Prompt الثاني
    });

    // إرجاع النص الناتج
    return finalDraftResponse.text;
  }
);
```

### ملخص التفاعل في المثال

|   |   |
|---|---|
|المكون|الدور في المثال|
|**Flow** (academicReviewGenerator)|يحدد التسلسل: 1. يرسل طلب البحث (Prompt 1). 2. ينتظر استدعاء الـ Tool. 3. يُنفذ الـ Tool. 4. يرسل النتائج للصياغة (Prompt 2). 5. يعيد النتيجة النهائية.|
|**Prompt 1**|يوجه الـ LLM إلى **عدم الإجابة** بل **استدعاء أداة** لتوفير البيانات.|
|**Tool** (academicSearchTool)|يوفر القدرة على "البحث عن بيانات خارجية" (أمر لا يستطيع الـ LLM القيام به ذاتياً) ويعيد سياقاً جديداً.|
|**Prompt 2**|يوفر السياق (نتائج الـ Tool) للـ LLM ويطلب منه تنفيذ مهمة الصياغة الأكاديمية النهائية.|

## 1. إعادة تصميم Flow لتقليل استدعاءات LLM

الاستهلاك الأكبر كان في استدعاء LLM مرتين (مرة للتخطيط ومرة للصياغة). يمكننا دمج أو إزالة خطوة التخطيط.

### الاستراتيجية: إلغاء دور LLM في التخطيط

بدلاً من مطالبة LLM بتحديد الكلمات المفتاحية للبحث (الاستدعاء الأول)، يمكننا أن نعهد بهذه المهمة إلى الـ **Tool** أو إلى الـ **Flow** نفسه باستخدام كود TypeScript بسيط. هذا ينقل العبء من النموذج المكلف إلى منطق التطبيق الرخيص.

#### مثال التعديل في Flow:

نعدل الـ Flow ليقوم بتمرير topic مباشرة إلى الأداة، أو يستخدم تقنية بسيطة لاستخلاص الكلمات المفتاحية (مثل تقسيم النص أو استخدام مكتبة لمعالجة اللغات الطبيعية خفيفة الوزن)، متجاوزين الـ **Prompt** الأول تماماً.

codeTypeScript

```
// Flow المعدل (يحذف الاستدعاء الأول لـ LLM)
export const academicReviewFlowOptimized = defineFlow(
  // ... (المدخلات والمخرجات)
  async ({ topic }) => {
    
    // **الخطوة 1 المُحسّنة: تجاوز LLM للتخطيط**
    const searchKeywords = extractKeywordsSimple(topic); // وظيفة بسيطة في Flow/TypeScript

    console.log('STEP 1: Directly executing tool with keywords:', searchKeywords);
    
    // **الخطوة 2: تنفيذ الأداة (academicSearchTool)**
    const toolResult = await academicSearchTool.run({ topic: searchKeywords });
    
    // **الخطوة 3: الصياغة النهائية (الاستدعاء الوحيد لـ LLM)**
    const finalDraftResponse = await generate({
      // ... (Model configuration)
      prompt: FINAL_DRAFT_PROMPT(topic, toolResult), 
    });

    return finalDraftResponse.text;
  }
);
// **النتيجة:** تم تقليل عدد استدعاءات LLM من اثنين إلى واحد، مما يوفر حوالي 50% من تكلفة المعالجة.
```

## 2. تحسين اختيار النموذج (Model Selection)

ليست كل نماذج LLM متساوية في التكلفة. النماذج المصممة للسرعة (مثل نماذج Flash) أرخص بكثير من النماذج المصممة للدقة والمنطق المعقد (مثل نماذج Pro).

### الاستراتيجية: استخدام نموذج تكلفة منخفضة للصياغة

نظراً لأن مهمة الصياغة النهائية (الاستدعاء الوحيد المتبقي) هي مهمة إبداعية ولكنها لا تتطلب منطقاً معقداً جداً (البيانات متوفرة بالفعل)، يمكننا استخدام نموذج أسرع وأقل تكلفة.

#### مثال التعديل في Genkit:

codeTypeScript

```
// استخدام gemini-2.5-flash بدلاً من gemini-2.5-pro
const finalDraftResponse = await generate({
  // استبدال gemini.chat() أو gemini.pro() بـ gemini.flash()
  model: gemini.flash(), 
  prompt: FINAL_DRAFT_PROMPT(topic, toolResult),
});
```

**النتيجة:** يمكن أن تقلل نماذج Flash تكلفة المعالجة بعامل 5 إلى 10 مقارنة بنماذج Pro، خاصة في المهام غير المنطقية.

## 3. تقليل حجم السياق (Token Efficiency)

تكلفة LLM مرتبطة مباشرة بعدد التوكنز التي يتم إدخالها (Prompt + Context) وإخراجها (Response).

### الاستراتيجية أ: تلخيص مُخرجات الأداة (Pre-Processing)

إذا كانت الأداة academicSearchTool تُرجع مئات الكلمات، فإن تمرير كل هذا النص إلى الـ LLM يرفع التكلفة بشكل كبير. يجب تلخيص بيانات الأداة قبل إرسالها للـ LLM.

#### طريقة التنفيذ:

1. **داخل الـ Tool:** تعديل الأداة لتقوم بإرجاع فقط البيانات الضرورية (العنوان، المؤلف، سنة النشر)، وليس الملخصات الطويلة.
    
2. **باستخدام LLM صغير للتلخيص:** إذا كان التلخيص ضرورياً، يمكن استخدام استدعاء ثالث (أو إضافته داخل الـ Flow) لنموذج صغير جداً (مثل gemma-2b) لتكثيف نتائج الأداة الطويلة إلى جملتين أو ثلاث قبل تمريرها لنموذج الصياغة النهائي.
    

### الاستراتيجية ب: فرض قيود على الطول في الـ Prompt

لضمان أن الـ LLM لا يكتب فقرات طويلة جداً وغير مطلوبة، يجب أن يكون الـ Prompt دقيقاً في تحديد طول المخرجات.

#### مثال التعديل على Prompt:

codeTypeScript

```
const FINAL_DRAFT_PROMPT = (topic: string, searchResults: string) => ({
  message: `... (السياق) ...
  قم بصياغة فقرة نقدية متماسكة ومحايدة. **يجب أن يتراوح طول الفقرة بين 150 و 170 كلمة بالضبط.** 
  تأكد من عدم تجاوز هذا الحد.`,
});
```

**النتيجة:** تحديد الطول يقلل من التوكنز الناتجة، ويجعل الاستهلاك المالي أكثر قابلية للتنبؤ.

## ملخص إجراءات توفير الاستهلاك

|   |   |   |
|---|---|---|
|إجراء التوفير|المكون المتأثر|التكلفة المقدرة للتوفير|
|**إلغاء خطوة التخطيط**|Flow / Prompt 1|توفير 50% من تكلفة الاستدعاءات.|
|**استخدام نموذج Flash**|LLM Selection|توفير 5x إلى 10x في سعر التوكن لكل استدعاء.|
|**تقليص مخرجات الـ Tool**|Tool / Context Input|تقليل عدد توكنز الإدخال إلى LLM.|
|**تحديد طول الإخراج**|Prompt / Response Output|تقليل عدد توكنز الإخراج وجعل التكلفة متوقعة.|

## 1. استخدام نموذج محلي داخل Genkit (Local LLMs)

لأسباب تتعلق بالخصوصية، التكلفة، أو زمن الاستجابة، قد نرغب في تشغيل نموذج صغير أو متوسط الحجم مباشرة على خادم التطبيق أو جهاز التطوير.

### الخيار الأفضل: استخدام Ollama

Ollama هي أداة مفتوحة المصدر تسهل تنزيل وتشغيل نماذج LLM (مثل Llama 3، Gemma، Mistral) محلياً عبر واجهة API بسيطة. Genkit يوفر تكاملاً مباشراً معها.

#### خطوات التنفيذ:

1. **تثبيت Ollama وتشغيل النموذج:**
    
    codeBash
    
    ```
    # تثبيت Ollama (راجع وثائقهم لنظام التشغيل)
    # تشغيل نموذج Gemma 2B محلياً (مثال)
    ollama run gemma:2b
    ```
    
2. **تثبيت موفر Ollama في Genkit:**
    
    codeBash
    
    ```
    npm install @genkit-ai/ollama
    ```
    
3. **إعداد Genkit لاستخدام Ollama:**  
    نقوم بتعريف النموذج في ملف genkit.config.ts.
    
    codeTypeScript
    
    ```
    // genkit.config.ts
    import { configureGenkit } from '@genkit-ai/core';
    import { ollama } from '@genkit-ai/ollama';
    
    configureGenkit({
      plugins: [
        ollama({
          models: [
            // تحديد النموذج الذي قمنا بتشغيله عبر Ollama
            { name: 'gemma-2b-local', model: 'gemma:2b' }, 
          ],
          // تحديد عنوان خادم Ollama (افتراضياً هو localhost)
          serverAddress: 'http://localhost:11434',
        }),
        // ... أي plugins أخرى
      ],
      // ...
    });
    ```
    
4. **استخدام النموذج المحلي في Flow:**  
    يمكن الآن استخدام هذا النموذج في أي Flow، مثل academicReviewFlowOptimized:
    
    codeTypeScript
    
    ```
    import { gemma2b } from '@genkit-ai/ollama'; // استيراد النموذج
    
    const finalDraftResponse = await generate({
      // استخدام النموذج المحلي المُعرف
      model: gemma2b, // أو 'gemma-2b-local' حسب التكوين
      prompt: FINAL_DRAFT_PROMPT(topic, toolResult),
    });
    ```
    

**الميزة:** توفير كامل لتكلفة API، خصوصية عالية، وزمن استجابة منخفض جداً (Latency).  
**التحدي:** يتطلب موارد حوسبة (RAM و CPU/GPU) عالية على السيرفر المستضيف.

## 2. استخدام نماذج استضافت ذاتياً عبر API (Self-Hosted Model Serving)

إذا كنا نستخدم نماذج كبيرة (مثل Llama 3 70B) التي لا يمكن تشغيلها بكفاءة عبر Ollama على سيرفر عادي، فإننا نحتاج إلى خادم نماذج متخصص (Model Serving Infrastructure).

### الخيار: استخدام VLLM أو TGI مع تكامل API

يمكننا استضافة النموذج على بنية تحتية مُسرّعة (مثل خوادم AWS أو Azure مع وحدات GPU قوية)، وتشغيل واجهة API قياسية مثل تلك التي يوفرها VLLM أو Text Generation Interface (TGI) من Hugging Face.

#### خطوات التنفيذ:

1. **تجهيز البنية التحتية:** تشغيل النموذج على خادم GPU وتفعيل نقطة نهاية (Endpoint) لواجهة برمجة تطبيقات (API).
    
2. **استخدام موفر مخصص أو Genkit/OpenAI Plugin:**  
    إذا كانت نقطة النهاية تحاكي واجهة OpenAI القياسية (وهو أمر شائع جداً في أدوات Serving)، يمكننا ببساطة استخدام موفر openai في Genkit وتوجيهه إلى السيرفر الخاص بنا.
    
    codeTypeScript
    
    ```
    // genkit.config.ts
    import { configureGenkit } from '@genkit-ai/core';
    import { openai } from '@genkit-ai/openai';
    
    configureGenkit({
      plugins: [
        openai({
          // توجيه Genkit لاستخدام الـ Base URL الخاص بالخادم المستضاف ذاتياً
          baseURL: 'https://my-custom-llm-server.com/v1', 
          apiKey: 'DUMMY_KEY', // قد لا نحتاج لمفتاح API إذا كان الخادم داخلياً
        }),
      ],
    });
    ```
    
3. **الاستخدام في Flow:**  
    نستخدم النموذج بالاسم الذي يعرفه موفر OpenAI (عادة ما يكون اسم الملف النموذج نفسه):
    
    codeTypeScript
    
    ```
    const finalDraftResponse = await generate({
      model: 'my-custom-llama-70b-endpoint', // اسم النموذج على الخادم الخاص بك
      prompt: FINAL_DRAFT_PROMPT(topic, toolResult),
    });
    ```
    

**الميزة:** القدرة على استخدام نماذج عملاقة دون تكلفة API طرف ثالث، والتحكم الكامل في زمن الاستجابة والأمان.  
**التحدي:** تكاليف التشغيل الأولية للبنية التحتية (GPU) وصعوبة الإدارة والصيانة.

## الخلاصة: دور Genkit في الاستضافة الذاتية

Genkit لا يقوم باستضافة أو تشغيل النماذج بنفسه، ولكنه يوفر **طبقة تجريدية (Abstraction Layer)** قوية تسمح لك بالتبديل بسهولة بين:

1. **الخدمات السحابية:** (Gemini, OpenAI, Azure).
    
2. **النماذج المحلية الخفيفة:** (عبر Ollama).
    
3. **النماذج المستضافة ذاتياً:** (عبر موفر OpenAI/Custom Endpoint).
    

هذا يعني أنك تستطيع تطوير الـ Flow الخاص بك باستخدام نموذج Gemini على السحابة، ثم الانتقال بسهولة إلى نموذج Gemma 2B محلياً على سيرفر الإنتاج بمجرد تغيير سطر واحد في التكوين.

Model

تثبيت وتشغيل نماذج الذكاء الاصطناعي على السيرفر المحلي يتطلب استخدام أدوات متخصصة لإدارة موارد الحوسبة (CPU/GPU) وتقديم واجهة API سهلة.

سنركز هنا على **أفضل طريقة وأسهلها للمطورين حالياً** وهي استخدام **Ollama**، نظراً لتكاملها السلس مع Genkit وقدرتها على التعامل مع نماذج مفتوحة المصدر (Open Source LLMs).

## خطوات تثبيت وتشغيل نموذج LLM محلياً باستخدام Ollama

هذه الخطوات تفترض أن لديك سيرفر محلي يعمل بنظام Linux أو macOS أو Windows.

### المرحلة الأولى: تجهيز البيئة وتثبيت Ollama

#### الخطوة 1: التحقق من المتطلبات الأساسية

تأكد من أن السيرفر لديه:

- **نظام تشغيل حديث:** Linux (مفضل)، macOS، أو Windows.
    
- **مساحة تخزين كافية:** النماذج تبدأ من 2GB (لـ Gemma 2B) وقد تصل إلى 40GB أو أكثر.
    
- **ذاكرة وصول عشوائي (RAM):** كلما زادت الـ RAM، كان الأداء أفضل (يفضل 16GB فما فوق).
    
- **وحدة معالجة رسوميات (GPU) (اختياري لكن موصى به):** إذا كان السيرفر يحتوي على GPU (NVIDIA أو AMD)، سيتم تسريع الأداء بشكل كبير.
    

#### الخطوة 2: تثبيت Ollama

Ollama هو برنامج خادم يُنزل النماذج ويشغلها في الخلفية.

**على Linux/WSL (الأكثر شيوعاً للسيرفرات):**

codeBash

```
curl -fsSL https://ollama.com/install.sh | sh
```

**على macOS/Windows:**  
قم بتحميل المثبت الرسومي من الموقع الرسمي لـ Ollama.

#### الخطوة 3: تشغيل نموذج LLM (التحميل والتفعيل)

بعد تثبيت Ollama، يمكنك الآن تنزيل وتشغيل أي نموذج متاح في مكتبتهم (مثل Llama 3، Mistral، أو Gemma).

سنستخدم هنا نموذج **Gemma 2B** لأنه خفيف وسريع:

codeBash

```
ollama run gemma:2b
```

عند تنفيذ هذا الأمر لأول مرة، سيقوم Ollama بما يلي:

1. **التنزيل:** تحميل ملفات النموذج (Gemma 2B) إلى السيرفر.
    
2. **التشغيل:** تشغيل النموذج. ستدخل مباشرة في وضع الدردشة التفاعلية.
    

**ملاحظة هامة:** بمجرد تشغيل أي نموذج عبر ollama run، يكون خادم Ollama (واجهة API) متاحاً تلقائياً على المنفذ الافتراضي http://localhost:11434.

#### الخطوة 4: الخروج من وضع الدردشة والتشغيل كخدمة

اكتب /bye أو اضغط Ctrl+D للخروج من وضع الدردشة التفاعلية.

يبقى خادم Ollama يعمل في الخلفية كخدمة (Daemon) وجاهز لتلقي طلبات API من تطبيقات مثل Genkit.

```
  // ...
```

في ملف الـ Flow الخاص بك (مثلاً flow.ts)، يمكنك الآن استيراد واستخدام النموذج المحلي الذي قمت بتعريفه.

```
export const academicReviewFlowOptimized = defineFlow(
    // ...
    async ({ topic }) => {
        // ... (تنفيذ Tool للحصول على البيانات)

        // **استخدام النموذج المحلي لتوليد النص**
```

## تحليل مواصفات جهازك

|   |   |   |
|---|---|---|
|المورد|المواصفة|التأثير على LLMs|
|**ذاكرة الوصول العشوائي (RAM)**|8 جيجابايت|**نقطة حرجة.** هذه الذاكرة كافية فقط لتشغيل النماذج الصغيرة جداً (Tiny/Nano) أو النسخ الكمية (Quantized) من النماذج الأصغر. لا يمكن تشغيل نماذج 7B أو أكبر بكفاءة.|
|**التخزين (Storage)**|140 جيجابايت|**كافي جداً.** لديك مساحة لتنزيل عدة نماذج صغيرة ومتوسطة الحجم.|
|**وحدة المعالجة (CPU/GPU)**|(غير محددة)|**مفترضة.** إذا لم يكن لديك GPU مخصص (مثل NVIDIA)، فسيتم الاعتماد على CPU، مما يعني أن زمن الاستجابة سيكون أبطأ بكثير مقارنة بالسيرفرات المجهزة بوحدات GPU.|

**الخلاصة:** يجب أن نركز على النماذج التي تتطلب **أقل من 6 جيجابايت** من ذاكرة الوصول العشوائي لتجنب تبديل الصفحات (Swapping)، مما يقتل الأداء.

## النماذج المناسبة (نماذج الفئة Nano/Tiny)

أفضل النماذج التي يمكنك تشغيلها بكفاءة على 8 جيجابايت RAM هي:

1. **Gemma 2B (Quantized/4-bit):** نموذج ممتاز من جوجل. يتطلب حوالي **2-3 جيجابايت RAM**.
    
2. **Llama 3 8B (Quantized/4-bit):** قد يكون ممكناً، لكنه سيستهلك معظم الـ RAM المتبقية بعد تشغيل نظام التشغيل والتطبيق. (أفضل تشغيله على 12-16GB RAM).
    
3. **Phi-3 Mini (Quantized/4-bit):** نموذج ممتاز من مايكروسوفت لأداء عالٍ بحجم صغير.
    

**التوصية:** نبدأ بـ **Gemma 2B** لضمان أفضل أداء واستقرار.

### ملاحظات هامة حول الأداء على جهازك

1. **زمن الاستجابة (Latency):** بما أنك تعتمد على CPU بشكل أساسي (ما لم يكن لديك GPU قوي)، فإن عملية توليد الفقرة الأكاديمية قد تستغرق بضع ثوانٍ (من 5 إلى 15 ثانية) حسب حجم النص المطلوب.

3. **نموذج الصياغة فقط:** تأكد أنك تستخدم هذا النموذج المحلي فقط لمهام الصياغة النهائية (حيث يكون السياق قصيراً)، وتجنب المهام المعقدة التي تحتاج إلى استدلال منطقي عميق.

## إرسال مطالبة (Prompt) ورؤية النتيجة عبر Ollama API

يستخدم Ollama نقطة النهاية /api/generate لتوليد النصوص. تتطلب هذه النقطة النهاية إرسال طلب POST بصيغة JSON.

### الخطوات:

#### الخطوة 1: تجهيز الطلب (JSON Payload)

يجب أن يحتوي طلبك على ثلاثة حقول رئيسية على الأقل:

1. model: اسم النموذج الذي تريد استخدامه (في حالتك: "gemma:2b").
    
2. prompt: النص الذي تريد أن يبدأ النموذج التوليد منه (مطالبتك).
    
3. stream: يجب تعيينه على false للحصول على الإجابة بالكامل دفعة واحدة (مفيد لـ curl).
    

#### الخطوة 2: إنشاء أمر curl

سنقوم بتكوين أمر curl لإرسال بيانات JSON إلى نقطة النهاية /api/generate.

**المطالبة المقترحة (للتجربة):** "اكتب مقدمة قصيرة عن أهمية الذكاء الاصطناعي في التعليم."

codeBash

```
# تأكد من أنك تستخدم علامات اقتباس مزدوجة داخل JSON
# واستخدام \ لفصل علامات الاقتباس حول النص
curl -X POST http://localhost:11434/api/generate -d '{
  "model": "gemma:2b",
  "prompt": "اكتب مقدمة قصيرة عن أهمية الذكاء الاصطناعي في التعليم.",
  "stream": false
}'
```

#### الخطوة 3: تنفيذ الأمر وعرض النتيجة

عند تنفيذ الأمر في الطرفية (Terminal)، سيقوم Ollama بمعالجة الطلب والرد باستجابة JSON تحتوي على النص المُولد.

**مثال على الاستجابة التي ستحصل عليها:**

codeJSON

```
{"model":"gemma:2b","created_at":"2026-01-09T18:00:00.00000000Z","response":"في عصر التحول الرقمي السريع، أصبح الذكاء الاصطناعي (AI) ليس مجرد تقنية مستقبلية، بل عنصراً أساسياً يعيد تشكيل المشهد التعليمي. تكمن أهميته في قدرته على تخصيص مسارات التعلم لكل طالب بشكل فردي، وتوفير أدوات تقييم فورية، وتحرير وقت المعلمين للتركيز على التفاعل الإنساني والتوجيه العميق. إن دمج الذكاء الاصطناعي في التعليم يمثل خطوة حاسمة نحو إعداد جيل قادر على مواجهة تحديات المستقبل بفاعلية.","done":true,"done_reason":"stop","total_duration":7810656000,"load_duration":1555026,"prompt_eval_count":15,"prompt_eval_duration":102142000,"eval_count":78,"eval_duration":7619429000}
```

**النتيجة التي تهمك:**

ابحث عن حقل "response" داخل الاستجابة. هذا هو النص الذي ولده نموذج gemma:2b بناءً على مطالبتك.

```
    {
      "role": "user",
      "content": "اكتب فقرة قصيرة عن أهمية الذكاء الاصطناعي في التعليم."
    }
  ],
  "stream": false
}'
```

### 2. التكويد (Encoding)

إذا كانت مطالبتك باللغة العربية تحتوي على رموز معقدة، قد تحتاج إلى التأكد من أن الطرفية تتعامل مع UTF-8 بشكل صحيح، أو أن تقوم بتخزين الـ JSON في ملف ومن ثم تمريره إلى curl باستخدام الخيار @filename.

**مثال لتمرير ملف JSON:**

1. إنشاء ملف prompt.json:
    
    codeJSON
    
    ```
    {
      "model": "gemma:2b",
      "prompt": "ما هي الأساليب الحديثة لتدريب النماذج اللغوية الكبيرة؟",
      "stream": false
    }
    ```
    
2. تنفيذ curl:
    
    codeBash
    
    ```
    curl -X POST http://localhost:11434/api/generate -d @prompt.json
    ```
    

هذه الخطوات تؤكد أن نموذجك المحلي يعمل بشكل سليم ومتاح للاستخدام من قبل تطبيق Genkit الخاص بك.

Model

هذه المكونات الثلاثة هي قلب تقنية **RAG (Retrieval-Augmented Generation)**، وهي الطريقة المثلى لتمكين نموذج اللغة الكبير (LLM) من استخدام معلوماتك الخاصة (مثل وثائقك الأكاديمية أو قاعدة البيانات الداخلية) لإنتاج إجابات دقيقة ومحدثة.

سنشرح هذه المكونات خطوة بخطوة في سياق Genkit، باستخدام المثال الذي لدينا (المراجعة الأدبية).

---

## مقدمة: RAG Flow في Genkit

لنفترض أنك تريد أن يبحث الـ LLM في **مكتبتك الخاصة من الأبحاث** بدلاً من الاعتماد على محركات بحث خارجية.

- **Embedder:** يحول كل ورقة بحثية في مكتبتك إلى متجه (Vector).
    
- **Indexer:** يخزن هذه المتجهات في قاعدة بيانات متجهات (Vector Store).
    
- **Retriever:** عند وصول طلب (سؤال)، يبحث عن المتجهات الأكثر تشابهاً مع السؤال في قاعدة البيانات.
    

---

## 1. Embedders: تحويل النصوص إلى متجهات (Vectors)

وظيفة Embedder هي إنشاء تمثيل رقمي (Vector/Embedding) لمعنى النص.

### الخطوة 1: تثبيت وتكوين Embedder

نحن بحاجة إلى نموذج LLM متخصص في التضمين. سنستخدم نموذج **gemini-2.5-flash** الذي يقدم أداء تضمين ممتازاً.

codeBash

```
# تثبيت موفر Gemini إذا لم يكن مثبتاً
npm install @genkit-ai/gemini
```

في ملف genkit.config.ts:

codeTypeScript

```
import { configureGenkit } from '@genkit-ai/core';
import { gemini, geminiEmbedder } from '@genkit-ai/gemini';
// ... (plugins/providers أخرى)

configureGenkit({
  plugins: [
    gemini({ apiKey: process.env.GEMINI_API_KEY }),
    // تعريف الـ Embedder
    geminiEmbedder({
      name: 'academic-embedder', // اسم مخصص لهذا Embedder
      model: 'models/text-embedding-004', // نموذج التضمين المخصص من Google
    }),
  ],
  // ...
});
```

الآن، لدينا Embedder جاهز باسم academic-embedder.

---

## 2. Indexers: بناء الفهرس (Vector Store)

Indexer يأخذ مجموعتك من الوثائق (Data) ويستخدم الـ Embedder لتحويلها إلى متجهات وتخزينها في قاعدة بيانات متجهات.

Genkit يدعم التكامل مع قواعد بيانات المتجهات مثل **Firestore (للتخزين البسيط)** أو **Pinecone/Weaviate (للتطبيقات الكبيرة)**. سنستخدم هنا خياراً شائعاً وبسيطاً مثل Firebase Firestore.

### الخطوة 2: تهيئة الـ Indexer

سنقوم بإنشاء فهرس يُسمى AcademicKnowledge، ويستخدم الـ Embedder الذي عرفناه في الخطوة 1.

codeTypeScript

```
// indexer.ts (مثلاً)
import { defineIndexer } from '@genkit-ai/core';
import { academicEmbedder } from '../genkit.config'; // افتراض أنك تستورد الـ Embedder المُكوَّن

// تعريف البيانات التي سيتم فهرستها
interface DocumentData {
  title: string;
  year: number;
  content: string;
}

export const academicIndexer = defineIndexer(
  {
    name: 'AcademicKnowledge',
    // تحديد الـ Embedder المستخدم
    embedder: academicEmbedder,
    // (اختياري) تحديد مصدر البيانات أو كيفية تخزين المتجهات
    // في مشاريع Genkit الكبيرة، يتم ربط هذا بـ Pinecone/Weaviate
  },
  async (flow) => {
    // هذا هو الـ Flow الذي يقوم بعملية الفهرسة الفعلية

    // 1. جمع قائمة بملفاتك أو وثائقك (هنا يتم محاكاة المصدر)
    const academicPapers: DocumentData[] = [
      { title: "أثر الـ AI على البحث", year: 2024, content: "يناقش هذا البحث..." },
      { title: "تقنيات RAG المتقدمة", year: 2023, content: "يستعرض الورقة..." },
      // ... المزيد من الوثائق
    ];

    // 2. تحويل الوثائق إلى مستندات Genkit (Chunks)
    const genkitDocuments = academicPapers.map(p => ({
        // النص الذي سيتم تضمينه (Embedding)
        text: `${p.title}. نشر في ${p.year}. المحتوى: ${p.content}`,
        // البيانات الوصفية (Metadata)
        metadata: { title: p.title, year: p.year },
    }));
    
    // 3. إضافة المستندات إلى الفهرس
    await flow.addDocuments(genkitDocuments);
  }
);
```

**كيفية تشغيل الـ Indexer:**

في بيئة التطوير، يمكنك تشغيل Indexer يدوياً عبر سطر الأوامر لمرة واحدة لإنشاء قاعدة المتجهات:

codeBash

```
genkit index run AcademicKnowledge
```

بمجرد التنفيذ، يتم بناء قاعدة المتجهات الخاصة بك.

---

## 3. Retrievers: استرجاع السياق

Retriever هي الواجهة التي تسمح للـ LLM بالبحث في الفهرس الذي بنيناه (AcademicKnowledge) والحصول على الوثائق ذات الصلة بالسؤال.

### الخطوة 3: تعريف الـ Retriever واستخدامه في Flow

الـ Retriever في Genkit غالباً ما يكون مجرد **مؤشر** إلى الفهرس الموجود.

codeTypeScript

```
// retriever.ts (مثلاً)
import { defineRetriever } from '@genkit-ai/core';
import { academicIndexer } from './indexer'; // استيراد الـ Indexer المُعرّف

export const academicRetriever = defineRetriever({
  name: 'academicRetriever',
  // ربط الـ Retriever مباشرة بالفهرس الذي أنشأناه
  indexer: academicIndexer,
  // يمكنك تحديد إعدادات البحث الافتراضية هنا (مثل عدد النتائج)
  config: {
    k: 3, // استرجع أكثر 3 وثائق ذات صلة
  }
});
```

### الخطوة 4: استخدام Retriever في Flow (RAG)

نعدل Flow academicReviewGenerator لاستخدام الـ Retriever بدلاً من Tool البحث الخارجي.

codeTypeScript

```
// flow.ts (نسخة RAG)
import { defineFlow, generate, retrieve } from '@genkit-ai/flow';
import { gemini } from '@genkit-ai/gemini';
import { academicRetriever } from './retriever'; // استيراد الـ Retriever

// ... (تكوين LLM و Prompts)

export const academicReviewRAGFlow = defineFlow(
  // ... (المدخلات والمخرجات)
  async ({ topic }) => {
    
    // 1. استرجاع الوثائق ذات الصلة (باستخدام Retriever)
    console.log(`STEP 1: Retrieving relevant documents for topic: ${topic}`);
    
    // Genkit يستخدم الـ Retriever لتحويل الـ topic إلى متجه والبحث به
    const retrievalResult = await retrieve({
      retriever: academicRetriever,
      query: `ما هي الأبحاث الحديثة المتعلقة بـ ${topic}؟`,
    });
    
    // استخلاص النصوص المسترجعة
    const retrievedContext = retrievalResult.documents
      .map(doc => doc.text)
      .join('\n---\n');

    console.log('STEP 2: Retrieved context:', retrievedContext);

    // 2. الصياغة النهائية (LLM + Context)
    // نستخدم الـ Prompt الذي يجمع السياق المسترجع
    const finalDraftResponse = await generate({
      model: gemini.flash(), 
      prompt: FINAL_DRAFT_PROMPT(topic, retrievedContext), 
    });

    return finalDraftResponse.text;
  }
);
```

## ملخص العلاقة بين المكونات

|   |   |   |
|---|---|---|
|المكون|وظيفته في RAG|متى يتم استخدامه؟|
|**Embedder**|إنشاء الفهم الرياضي للنص.|عند بناء الفهرس (Indexing) وعندما يريد الـ Flow البحث (Querying).|
|**Indexer**|بناء وتحديث قاعدة بيانات المتجهات.|يدوياً، عند إضافة وثائق جديدة، أو كجزء من عملية ETL للبيانات.|
|**Retriever**|البحث عن السياق ذي الصلة.|داخل الـ Flow، قبل استدعاء نموذج اللغة الكبير، لتزويده بالمعلومات.|

هذا سؤال مهم جداً عند العمل مع النماذج المحلية الصغيرة، لأن ضمان تنسيق المخرجات (Output Formatting) أمر بالغ الأهمية لأتمتة العمليات في Flow.

نماذج Ollama، ومن ضمنها gemma:2b، تدعم توليد JSON بشكل ممتاز، ولكن بما أن gemma:2b نموذج صغير (Tiny LLM)، قد يحتاج إلى توجيه أكثر دقة لضمان النتيجة الصحيحة.

هناك طريقتان رئيسيتان لإجبار Ollama/Gemma على الإخراج بصيغة JSON باستخدام Genkit:

---

## الطريقة 1: استخدام ميزة JSON Mode في Ollama (الأفضل والأكثر كفاءة)

Ollama يدعم تمرير خيار format: json في استدعاء الـ API. عندما تستخدم Genkit موفر Ollama، يمكنك تفعيل هذا الخيار في إعدادات التوليد (Generation Configuration).

### الخطوات في Genkit:

#### الخطوة 1: تعريف الهيكل المطلوب (Schema)

أولاً، يجب أن تعرف بالضبط شكل JSON الذي تتوقعه باستخدام Zod (مكتبة التحقق من المخططات المستخدمة في Genkit).

لنفترض أنك تريد مراجعة أدبية في شكل JSON يتضمن العنوان والفقرة النصية والمراجع المستخدمة:

codeTypeScript

```
import * as z from 'zod';

const LiteratureReviewSchema = z.object({
  title: z.string().describe("العنوان المقترح للمراجعة الأدبية."),
  review_paragraph: z.string().describe("النص الأساسي للمراجعة الأدبية."),
  references_used: z.array(z.string()).describe("قائمة العناوين التي تم استخدامها كمراجع."),
});
```

#### الخطوة 2: استخدام responseSchema في generate

داخل الـ Flow الخاص بك، عند استدعاء generate، يمكنك تمرير الـ Schema المطلوب. موفر Ollama في Genkit سيعرف تلقائياً كيفية تمرير format: json إلى Ollama API.

codeTypeScript

```
// flow.ts
import { generate } from '@genkit-ai/flow';
import { gemma2b } from '@genkit-ai/ollama';
import { LiteratureReviewSchema } from './schemas'; // استيراد الـ Schema

const finalDraftResponse = await generate({
  model: gemma2b, 
  prompt: FINAL_DRAFT_PROMPT(topic, toolResult), 
  config: {
    // 1. تفعيل وضع JSON
    responseSchema: LiteratureReviewSchema, 
    // 2. توجيه إضافي للنماذج الصغيرة (اختياري لكن مفيد)
    output: {
      format: 'json', 
      schema: LiteratureReviewSchema.passthrough(), // تأكيد التنسيق
    }
  },
});

// ستكون النتيجة الآن كائن TypeScript تم التحقق منه
const reviewObject = finalDraftResponse.output; 
console.log(reviewObject.review_paragraph);
```

**ملاحظة:** يضمن Genkit أن النص الذي يخرج من Ollama يتم تحويله وتحقق صحته (Validation) وفقاً للـ Schema قبل تمريره كـ output.

---

## الطريقة 2: استخدام التوجيه في الـ Prompt (Prompt Engineering)

هذه الطريقة تقليدية وتعمل مع أي نموذج، وهي ضرورية لتدريب النموذج على إنتاج JSON قبل تفعيل ميزة json_mode الخاصة بالـ API.

### الخطوات:

#### الخطوة 1: تعديل الـ Prompt ليشمل تعليمات صارمة

يجب أن تكون التعليمات واضحة ولا لبس فيها، مع تقديم مثال (Few-shot example) للهيكل المطلوب.

codeTypeScript

```
const FINAL_DRAFT_PROMPT_JSON = (topic: string, searchResults: string) => ({
  message: `باستخدام نتائج البحث الأكاديمي التالية:
  ---
  ${searchResults}
  ---
  مهمتك هي صياغة مراجعة أدبية حول الموضوع: "${topic}".

  **يجب عليك الالتزام الصارم بما يلي:**
  1. يجب أن يكون الإخراج بصيغة JSON فقط.
  2. لا تقم بكتابة أي نص أو مقدمات قبل أو بعد كتلة JSON.
  3. يجب أن يطابق هيكل JSON التالي:
  
  """
  {
    "title": "...",
    "review_paragraph": "...",
    "references_used": ["...", "..."]
  }
  """
  `,
});
```

#### الخطوة 2: استدعاء الـ Flow دون responseSchema (اختياري)

إذا لم تستخدم responseSchema (الطريقة 1)، فإن الـ LLM سيخرج نص JSON الخام. ستحتاج إلى تحليل هذا النص يدوياً:

codeTypeScript

```
const finalDraftResponse = await generate({
  model: gemma2b, 
  prompt: FINAL_DRAFT_PROMPT_JSON(topic, toolResult),
});

try {
    // التحليل اليدوي للنص الخام
    const jsonText = finalDraftResponse.text.trim();
    const reviewObject = JSON.parse(jsonText);
    console.log("Successfully parsed JSON.");
} catch (e) {
    console.error("Failed to parse JSON from LLM response:", e);
    // التعامل مع الأخطاء (مثل محاولة تنظيف النص يدوياً إذا كان النموذج قد أضاف مقدمة)
}
```

## الخلاصة والتوصية

**التوصية الأقوى:** **استخدم الطريقة 1 (Genkit responseSchema مع Ollama).**

- **لماذا؟** لأنها تستخدم ميزات API الأصلية لـ Ollama لضمان مخرجات JSON بشكل أفضل وأكثر كفاءة (باستخدام JSON Mode الحقيقي)، و Genkit يتولى مهمة التحقق من الصحة والتحويل إلى كائن TypeScript لك.
    
- **دمج الطريقتين:** للحصول على أفضل النتائج مع نموذج صغير مثل gemma:2b، يفضل **دمج الطريقة 1** (استخدام responseSchema) **مع توجيهات واضحة في الـ Prompt** (الطريقة 2) لتقليل فرص انحراف النموذج عن التنسيق المطلوب.
