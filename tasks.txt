                                                                                    Context

The Arkan builder workspace is composed of the following layout components located in src/modules/ai-content/adapters/components/builder/layout/:

 • BuilderWorkspace.tsx — Root orchestrator. Manages fullscreen, onboarding, zoom, and composes all layout pieces.
 • BuilderLayout.tsx — Structural shell. Three-zone flex row: left sidebar → canvas → right sidebar. Uses Framer Motion for animated entry/exit.
 • BuilderHeader.tsx — Top bar. Project name editing, save status, and actions.
 • BuilderSidebar.tsx — Collapsible side panels (left/right). Wraps CollapsibleSidePanel, drives width transitions, has a "Stable Manifest" footer.
 • BuilderCanvas.tsx — Central viewport. Zoom orchestration, scroll area, dot-grid atmosphere, crop marks, floating zoom HUD.
 • SidebarContainer.tsx — Inner panel wrapper. Dot-grid, sticky technical header, scrollable content.
 • SidebarSection.tsx — Collapsible grouping within a panel. Animated height, high-density labels.
 • types.ts — Shared prop interfaces (SidebarPanelConfig, BuilderSidebarProps).

                                                                               Refactoring Goals

Please refactor these components to professional engineering standards with the following objectives:

───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
                                                                   1. 🔧 Structural & Responsibility Clarity

 • BuilderWorkspace.tsx is doing too much: fullscreen logic, onboarding state, snapshot lookup, profiler instrumentation, suggestion computation, and layout composition.
   Extract each concern into a dedicated hook or sub-component:
    • useFullscreen(ref) → handles requestFullscreen, exitFullscreen, and fullscreenchange event.
    • useOnboarding() → handles localStorage check, showOnboarding state, and handleOnboardingComplete.
    • Move suggestion computation into useReportGenerator or a dedicated useDocumentSuggestion(project) hook.
    • Remove the <Profiler> wrapper in production builds (gate it with process.env.NODE_ENV === 'development').
 • BuilderLayout.tsx should accept an optional leftSidebar and correctly handle the case where neither sidebar is present (full-width canvas).
 • BuilderCanvas.tsx has two zoom-reset controls (RotateCcw and the percentage button) that both call onZoomReset. Consolidate into one canonical reset action and clarify
   intent with distinct aria-label values.

───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
                                                                     2. 📐 CSS Variables & Sizing Hygiene

 • The CSS variables --sidebar-w, --sidebar-w-left, and --workspace-h are defined inline on the BuilderLayout root div. Move these into the global CSS (globals.css) or a
   dedicated design-token layer so they are available to child components without prop drilling or var() assumptions.
 • The BuilderSidebar and BuilderCanvas currently duplicate the 28px dot-grid background style inline. Extract this into a reusable Tailwind utility class or a shared
   <AtmosphericGrid /> primitive component to eliminate duplication across 4+ components.

───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
                                                                     3. 🎬 Motion & Animation Consistency

 • BuilderLayout uses mode="popLayout" for sidebar AnimatePresence. Validate that this does not cause layout shifts when the right sidebar transitions between panels. Consider
   mode="wait" if jumps occur.
 • All motion transitions use ease: [0.22, 1, 0.36, 1] (spring-like cubic bezier). Extract this into a shared constant:
   ```ts
   // src/modules/ai-content/adapters/components/builder/layout/motion.ts
   export const SPRING_EASE = [0.22, 1, 0.36, 1] as const;
   export const PANEL_TRANSITION = { duration: 0.5, ease: SPRING_EASE };
   ```
 • SidebarSection uses duration: 0.5 for height animation. Reduce to 0.3 for snappier section toggling which is more standard for collapsible UIs.

───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
                                                                       4. ♿ Accessibility Improvements

 • SidebarSection: The <button> already handles onClick, so the onKeyDown for Enter is redundant — native buttons fire onClick on Enter. Remove the redundant handler.
 • SidebarSection: Add aria-expanded={isOpen} and aria-controls pointing to the content id for proper screen reader announcement.
 • BuilderCanvas Zoom HUD: The <button> for zoom reset percentage is missing aria-label. Add aria-label="Reset zoom to 100%".
 • BuilderSidebar footer: The ShieldCheck icon and version label are decorative. Ensure they have aria-hidden="true".
 • SidebarContainer header: The <h2> is semantically correct, but ensure heading hierarchy is consistent with the page (should be <h2> if the page has an <h1>, otherwise
   adjust).

───────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────
                                                                  5. 🧩 Type Safety & Interface Completeness

 • BuilderCanvas: The containerRef prop type is React.RefObject<HTMLDivElement> but the component also has its own ref via forwardRef. The dual-ref pattern is confusing —
   document when each is used or consolidate.
 • types.ts: SidebarPanelConfig.icon is typed as ReactElement but is passed directly as JSX. Widen to ReactNode for flexibility, or narrow to React.ReactElement<{ className?:
   string }> to allow icon size overrides.
 • BuilderSidebarProps: defaultSize and onResize are defined but never consumed anywhere in BuilderSidebar.tsx. Either implement resizable sidebar logic or remove these dead
   props.
