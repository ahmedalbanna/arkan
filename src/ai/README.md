# تنظيم مجلد `src/ai`

هذا الملف يشرح التغييرات المنطقية التي قمت بها في إعادة هيكلة مجلد `src/ai` ويوفر إرشادات سريعة للمطورين.

الهدف
- تحسين قابلية الاستخدام: استخدام ملفات "barrel" (index.ts) لتصدير مجموعات من الوحدات بدلاً من استيراد ملفات فردية مباشرة.
- أسماء أوضح: إضافة ملف تغليف باسم `generator.ts` الذي يعيد تصدير `genkit.ts` باسم أوضح.
- فصل المخاوف: تنظيم الصادرات عبر `flows` و`schemas` و`dev` لسطح استيراد واحد.

ما الذي تغير
- `src/ai/index.ts` — مدخل علوي يتيح:
  - import { ... } from 'src/ai' أو import * as ai from 'src/ai'
  - كما يتضمن `flows` و`schemas` كمساحات اسمية: `import { flows } from 'src/ai'`.
- `src/ai/generator.ts` — ملف تغليف يوصى باستيراده باسم `generator` بدلًا من `genkit` في كود جديد.
- `src/ai/flows/index.ts` — يجمع كل وحدات الـ flows في مكان واحد: استورد كـ `import * as flows from 'src/ai/flows'`.
- `src/ai/schemas/index.ts` — يجمع ملفات schemas/ في مدخل واحد.
- `src/ai/dev/index.ts` — مدخل لوحدات التطوير.

ملاحظات توافقية
- كل الملفات الأصلية لم تُحذف أو تُغير؛ ما تم إضافته هو ملفات تغليف/تصدير فقط. هذا يضمن أن أي استيراد موجود سيظل يعمل كما قبل.
- التغيير الموصى به للكود الجديد: استيراد عبر الباريلز الجديدة. مثال:

```ts
// قديم
import analyzeContext from 'src/ai/flows/analyze-context';

// جديد (موصى به)
import { analyzeContext } from 'src/ai/flows';
```

مقترحات إستكمال لاحقة
- (اختياري) إعادة تسمية الملفات داخل المجلد `flows` إلى نمط ثابت (مثلاً camelCase أو kebab-case) وإنهاء عمليات تحديث الاستيراد عبر المشروع.
- إنشاء اختبارات بسيطة للتحقق من أن كل ملف export في `flows` و`schemas` يصل إليه بنجاح.

إذا أردت، أستطيع متابعة:
- تحديث الاستيرادات عبر المشروع لاستخدام الباريلز الجديدة.
- إضافة اختبارات وحدة بسيطة لأسطح التصدير.
