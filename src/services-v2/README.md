# Services Architecture v2.0 - Arkan

## نظرة عامة على الهيكل الجديد

تم إعادة هيكلة مجلد `services` بالكامل لتحسين القابلية للتوسع والصيانة. الهيكل الجديد يتبع مبادئ الفصل الواضح للمسؤوليات ويسمح بالتوسع الأفقي بسهولة.

## فئات الخدمات

### 1. Core Services (`/core/`)
خدمات البنية التحتية الأساسية التي يعتمد عليها باقي النظام.

- **base-service.ts** - الخدمة الأساسية المشتركة
- **api-client.ts** - عميل API موحد
- **error-handler.ts** - معالجة الأخطاء المركزية
- **logger.ts** - نظام التسجيل
- **cache-manager.ts** - إدارة التخزين المؤقت

### 2. Infrastructure Services (`/infrastructure/`)
خدمات البنية التحتية والتكاملات الخارجية.

- **auth/** - خدمات المصادقة والجلسات
- **database/** - خدمات قاعدة البيانات
- **storage/** - خدمات التخزين السحابي
- **monitoring/** - مراقبة الأداء والأخطاء
- **external-apis/** - تكاملات الخدمات الخارجية

### 3. Business Services (`/business/`)
خدمات الأعمال والوظائف الأساسية للتطبيق.

- **users/** - إدارة المستخدمين والملفات الشخصية
- **projects/** - إدارة المشاريع والمحتوى
- **teams/** - إدارة الفرق والتعاون
- **templates/** - إدارة القوالب
- **payment/** - خدمات الدفع والائتمانات
- **analytics/** - تحليل البيانات والإحصائيات

### 4. Intelligent Services (`/intelligent/`)
خدمات الذكاء الاصطناعي والتعلم الآلي المتقدمة.

- **ai-core/** - نواة نظام الذكاء الاصطناعي
- **context-analysis/** - تحليل السياق المتقدم
- **generation/** - توليد المحتوى الذكي
- **quality-assessment/** - تقييم جودة المخرجات
- **caching/** - تخزين مؤقت ذكي
- **optimization/** - تحسين الأداء والجودة

### 5. Legacy Services (`/legacy/`)
الخدمات القديمة التي تحتاج إعادة هيكلة أو إزالة.

- **old-services/** - الخدمات التي سيتم نقلها أو حذفها

## مبادئ التنظيم

### 1. الفصل الواضح للمسؤوليات
- كل فئة لها مسؤوليات محددة وواضحة
- عدم وجود تداخل بين فئات الخدمات
- كل خدمة تعرف مسؤولياتها بوضوح

### 2. التوسع الأفقي
- يمكن إضافة خدمات جديدة في نفس الفئة دون تأثير الآخرين
- كل فئة يمكن أن تنمو بشكل مستقل
- سهولة في إضافة خدمات جديدة

### 3. التبعية الواضحة
- الخدمات في المستويات العليا تعتمد على المستويات الأدنى فقط
- عدم وجود تبعيات دائرية بين الخدمات
- سهولة في اختبار وصيانة كل خدمة بشكل مستقل

### 4. التسمية المتسقة
- أسماء واضحة ووصفية للمجلدات والملفات
- اتباع اصطلاحات التسمية الموحدة
- استخدام اللغة العربية في التعليقات والتوثيق

## خطة الانتقال

### المرحلة 1: إنشاء الهيكل الجديد
- إنشاء جميع المجلدات والملفات الأساسية
- نقل الخدمات المشتركة إلى `/core/`
- نقل خدمات البنية التحتية إلى `/infrastructure/`

### المرحلة 2: نقل خدمات الأعمال
- نقل خدمات المستخدمين، المشاريع، الفرق، إلخ إلى `/business/`
- تحديث التبعيات والاستيرادات

### المرحلة 3: دمج الخدمات الذكية
- دمج جميع الخدمات الذكية في `/intelligent/`
- تحسين التكامل بين الخدمات الذكية

### المرحلة 4: التنظيف والتوثيق
- إزالة الملفات المكررة
- تحديث التوثيق
- اختبار شامل للنظام الجديد

## فوائد الهيكل الجديد

### 1. تحسين القابلية للتوسع
- إضافة خدمات جديدة أصبحت أسهل وأسرع
- تقليل التأثير على باقي النظام عند إضافة خدمات جديدة
- تحسين الأداء من خلال تحميل الخدمات حسب الحاجة

### 2. سهولة الصيانة
- فصل واضح للمسؤوليات يجعل الصيانة أسهل
- اختبار كل فئة بشكل مستقل
- توثيق أفضل وأكثر تنظيماً

### 3. تحسين الأداء
- تحميل الخدمات فقط عند الحاجة
- تقليل حجم الباقة المرسلة للمتصفح
- تحسين استخدام الذاكرة

### 4. تعزيز الأمان
- فصل أفضل للصلاحيات والأذونات
- تحكم أفضل في الوصول للخدمات الحساسة
- سهولة في تطبيق سياسات الأمان

## مثال على الاستخدام

```typescript
// استيراد من الفئات المختلفة
import { BaseService } from '@/services-v2/core/base-service';
import { AuthService } from '@/services-v2/infrastructure/auth/auth-service';
import { ProjectService } from '@/services-v2/business/projects/project-service';
import { IntelligentReportService } from '@/services-v2/intelligent/generation/report-service';

// استخدام الخدمات
const reportService = new IntelligentReportService();
const userService = new UserService();
```

هذا الهيكل يوفر أساساً قوياً لتطوير وتوسيع النظام بشكل مستدام وفعال.
