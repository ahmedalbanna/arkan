# Hooks & State Management Guide

This document provides an overview of the custom React hooks and state management patterns used in this project. The architecture is designed to be scalable, maintainable, and efficient, primarily using **TanStack React Query** for server state and **Zustand** for global client state.

## Core Principles

1.  **Separation of Concerns**:
    *   **Services (`src/services`)**: Handle direct API communication (`fetch` calls). They are simple async functions responsible for one thing: talking to an API endpoint.
    *   **Hooks (`src/hooks`)**: Use services to interact with APIs and manage the React Query cache (`useQuery`, `useMutation`). They connect the data layer to the UI layer but don't contain `fetch` logic themselves.
    *   **Components (`src/components`)**: Use hooks to get data and mutations. They are responsible for rendering the UI and handling user events, not for fetching data directly.
2.  **Centralized Query Keys**: All React Query keys are generated by factories in `src/lib/query-keys.ts` to ensure consistency and prevent typos.
3.  **Centralized State Management**:
    *   **Zustand**: Used for complex global UI state that needs to be shared across many components (e.g., the state of the document builder). We have several stores, each managing a specific feature's state (`useBuilderStore`, `useReportStore`, etc.) to keep concerns separated.
    *   **React `useState`**: Used for simple, component-local state (e.g., managing a dialog's open/closed state).
4.  **Standardized Error Handling**: A utility function in `src/lib/errorUtils.ts` is used by all hooks to provide consistent toast notifications for errors.

## TanStack React Query Hooks

These hooks are responsible for all server-side data fetching, caching, and state synchronization.

### `use-agents.ts`

-   **Purpose**: Manages fetching and updating AI agents' configurations.
-   **`useAgents()`**: Fetches a list of all agents. Used in the admin agent manager.
-   **`useAgent(agentId)`**: Fetches details for a single agent. Used in the agent editor.
-   **`useUpdateAgent()`**: A mutation hook for updating an agent's details (name, prompt, enabled status).

### `use-features.ts`

-   **Purpose**: Manages application feature flags.
-   **`useFeatures()`**: Fetches the list of all available features and their current status (`isEnabled`). Used by the main Builder page to conditionally render UI tabs.
-   **`useUpdateFeature()`**: A mutation hook for toggling a feature on or off. It uses an **optimistic update** to make the UI feel instantaneous.

### `use-projects.ts`

-   **Purpose**: Manages CRUD (Create, Read, Update, Delete) operations for user projects.
-   **`useProjects()`**: Fetches a list of all projects for the currently authenticated user.
-   **`useProject(projectId)`**: Fetches the complete data for a single project.
-   **`useSaveProject()`**: A mutation for creating a new project in the database.
-   **`useUpdateProject()`**: A mutation for saving changes to an existing project.
-   **`useDeleteProject()`**: A mutation for deleting a project.

### `use-templates.ts` & `use-docx-styles.ts` & `use-pptx-styles.ts`

-   **Purpose**: These hooks manage the fetching and updating of various document and presentation styling templates used for exporting content.
-   **`use...Templates()` / `use...Styles()`**: Fetch the respective templates (e.g., `useProposalTemplates`, `useDocxStyles`).
-   **`useUpdate...Template()` / `saveChanges()`**: Mutations to save modifications made by an admin to a template's configuration or styles.
-   **`useRefresh...Image()`**: A mutation to call an AI image generation flow and update the preview image for a template.

### `use-transactions.ts`

-   **Purpose**: Manages payment transaction data, primarily for admin verification.
-   **`useVerifyPayment()`**: A mutation hook used by admins to approve or reject a pending payment transaction. On success, it invalidates user and transaction queries to refresh the UI.

### `use-translation.ts`

-   **Purpose**: Provides a simple mutation hook for translating text via an AI flow.
-   **`useTranslate()`**: Takes text and a target language, calls the translation API, and returns the result. Used for inline translations throughout the app.

### `use-user.ts`

-   **Purpose**: The central hub for all user authentication and profile management.
-   **`useUserProfile(userId)`**: Fetches a user's public profile data.
-   **Mutations**: Includes hooks for all auth actions: `useLogin`, `useGoogleSignIn`, `usePhoneSignIn`, `useSignup`, `useLogout`, `useForgotPassword`, etc. These hooks handle the full lifecycle, including calling Firebase Auth, updating the session, and navigating the user.

## Zustand Client-Side State Stores

These stores manage global UI state that is not directly tied to the server.

-   **`useBuilderStore.ts`**: The main store. It holds the core project data being actively worked on (proposal, project idea, etc.) and orchestrates the state of the other stores. It's responsible for the "New Session" and "Load Project" logic.
-   **`useReportStore.ts`**: Manages all state related to the Report Generator tab, including the generated text for each section, the state of UI controls (like sliders and dropdowns), and the selected context for generation.
-   **`useDiagramStore.ts`**: Holds the state for all generated diagrams, including their PlantUML code and image URLs.
-   **`usePresentationStore.ts`**: Manages the state for the Presentation Generator, including the history of generated presentations and the currently active one.
-   **`useCodeGeneratorStore.ts`**: Manages the state for the Code Generator, including the user's prompt and the resulting HTML/CSS/JS.
-   **`useExamSolverStore.ts` & `useHomeworkSolverStore.ts`**: Manage the state for their respective features, tracking the workflow from file upload to analysis and final solution, including a history of past sessions.

## Utility Hooks

-   **`use-autosave.ts`**: Listens for changes in the `useBuilderStore` and triggers a debounced save/update operation to the database, providing a seamless autosave experience.
-   **`use-debounce.ts`**: A generic utility hook to delay the update of a value, used by `useAutosave`.
-   **`use-mobile.ts`**: A simple hook to detect if the user is on a mobile-sized screen.
-   **`use-sound.ts`**: Manages playing UI sounds for feedback on actions like success or error.
-   **`use-toast.ts`**: A provider and hook for the application-wide notification (toast) system.
